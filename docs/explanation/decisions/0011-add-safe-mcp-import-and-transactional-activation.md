# ADR-011：安全导入 MCP 配置并以测试作为启用门槛

## 状态

Accepted

## 日期

2026-09-08

## 背景

ADR-008 将 MCP 实例迁入 DSH Settings，但首版仍要求用户把第三方提供的
`mcpServers` 配置逐字段改写到内部表单。第三方模板的包装层级、JSONC、凭据
占位符、Windows 路径和 transport 命名并不统一，手工转换容易产生不能启动、
秘密明文持久化或配置保存后仍未启用等问题。

首版还将测试、保存和启用拆成独立操作。测试通过不保证随后保存的内容相同，
编辑已启用实例时也可能先覆盖可用配置，再把启动失败暴露为运行状态。Client
自行实现基础控件，操作反馈与 DSH Web 其他设置页面不一致。

## 决策

- 添加确定性的 MCP 配置导入器，接受 JSON、JSONC、Markdown 代码块、完整
  `mcpServers`、带名称的多个 server 和单个 server 对象。
- 导入器只自动执行不改变运行语义的规范化。未知启动字段、不支持的 transport、
  凭据占位符和可疑路径转义形成阻塞项；不得静默丢弃、覆盖或猜测。
- 多实例配置可批量保存为禁用。单实例可以通过一次执行确认完成
  “临时测试、持久化、启用”；测试失败不得写入配置或凭据。
- 执行确认绑定 action、实例 ID、settings revision、启动配置和凭据变更；确认
  不能跨实例或跨版本复用。
- 已启用实例修改启动配置时，先用候选配置测试；测试失败时保留当前持久配置和
  运行中的子 Fiber。
- Settings watcher 的 runtime reconcile 与 RPC 写操作进入同一串行队列，避免
  长时间 probe 期间由过期设置快照提前切换子 Fiber。
- 非敏感环境变量可以 literal 形式保存；敏感名称仍必须使用 DSH credentials。
  HTTPS 允许任意合法 Header 名称使用 credential；literal Header 仍受安全
  allowlist 限制。明文 HTTP 不得携带 credential，URL 继续禁止凭据、查询参数
  和 fragment，probe 继续拒绝重定向。
- 导入的秘密只存在于当前编辑会话和 Host 操作内存中，不进入日志、修复报告、
  技术详情、URL 或浏览器持久存储。Client 仍不能读取或提交 credential ref。
- Web Client 使用 DSH UI primitives 提供 Button、Modal、Toast、StateDot、
  Menu 和 Tooltip；MCP 自定义样式只承担布局和字段展示。
- UI 区分期望启用状态与可观察运行状态。只能宣称“已启动”，不能把子 Fiber
  已加载描述为持续“已连接”。

## 备选方案

- **继续只提供结构化表单**：实现简单，但没有解决第三方配置迁移的主要成本。
- **接受任意文本并尽量猜测**：表面成功率更高，但可能执行与用户输入不同的
  命令，不能作为安全默认值。
- **测试后由 Client 依次调用 create 与 set-enabled**：会产生两次确认，并在
  中间状态、revision 竞争或第二步失败时留下禁用实例。
- **先保存再测试已启用实例**：无法满足失败时保留旧配置运行的事务语义。
- **所有环境变量继续强制作为凭据**：保守但把 `LOG_LEVEL` 等普通设置混入
  credentials，降低第三方配置兼容性和可理解性。

## 结果

Host 需要提供导入预检和组合式测试/写入操作，并对凭据写入、settings revision
和 runtime 切换执行补偿。已有实例结构保持兼容；新增 literal 环境变量无需
迁移旧数据。

导入器的提示是安全边界的一部分，必须使用固定错误代码并保持脱敏。行为变更需
覆盖解析、占位符、未知字段、HTTP 安全约束、测试失败不落盘、revision 冲突
回滚和旧运行实例保留等测试。发布前还需通过浏览器验证异步反馈、焦点管理、
键盘操作和常见视口高度。

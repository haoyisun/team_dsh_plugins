# ADR-009：在 DSH 设置中管理外源插件

## 状态

Accepted

## 日期

2026-09-07

## 背景

ADR-006 使用仓库注册表和显式同步命令管理 npm 外源插件。该方案可审查且可重复，但把本机运行状态投射到 Git 配置，要求用户编辑 YAML、维护 Bundle entry 身份并执行多条命令。外源插件本质上属于当前用户的 DSH Web Profile，不应由仓库清单充当第二事实来源。

DSH 官方 `plugin --profile web` 命令负责在 Profile 中运行 pnpm，并在成功后对账 Bundle。运行中的 DSH 不会热加载 Bundle 增删和版本变化，因此操作后仍需重启。

## 决策

- 新增工作区插件 `@team-dsh-plugins/plugin-manager`，通过 `settings.section` 在 DSH 设置中提供“插件管理”。
- 以 Web Profile 的 `package.json`、已安装包 manifest、Bundle patch 和顶层 Profile patch 为实际状态来源，不维护外源插件注册表。
- 只管理 npm registry 包名、`latest` 或精确 semver；拒绝范围、tag、URL、Git spec、本地路径和 `@team-dsh-plugins/*`。
- 预检通过 Profile 的 pnpm 配置解析精确版本，并要求目标 manifest 声明位于包目录内的 `dsh.bundle.patch`。
- 添加、删除和版本变更调用当前运行实例对应的官方 DSH CLI，不调用可能漂移版本的无约束 `npx`。
- 变更全局串行。服务端确认令牌绑定操作、包名和版本，五分钟过期且只能使用一次；CLI 最长执行五分钟，完成或失败后重新读取实际状态。
- 执行或状态核对失败时，以操作前的直接依赖、Bundle 注册和精确已安装版本为快照执行补偿：新增失败移除残留，版本变化失败重新安装先前版本。补偿完成后再次核对实际状态；删除和修复不尝试还原为此前的缺失或损坏文件。无法恢复时将脱敏错误和检测到的实际状态明确返回 UI。
- 第三方包、依赖及生命周期脚本属于代码执行信任边界。UI 显示风险提示；成功不返回 CLI 输出，失败只返回有长度限制且脱敏的技术详情。
- DSH 系统 Bundle、工作区插件和管理器自身只读。外源包按 npm 包整体管理，不单独管理 Bundle entries 或传递依赖。
- 每个包只保存一个上一版本号用于恢复；安装状态仍以 Web Profile 为准。卸载不删除插件设置、凭据或业务数据。
- 变更完成后在插件行保留待重启状态，不让插件尝试重启其宿主进程。重启前允许撤销可逆的添加和版本变化；删除和修复只展示待生效状态，其他插件仍可继续管理。

## 迁移

- 删除 `profiles/web.external.yml`、`pnpm run sync:external` 及其实现和操作文档。
- `pnpm run init` 删除旧的空外源覆盖受管块。
- 旧受管块存在禁用项时，移除仓库所有权标记但保留这些顶层 patch，以免迁移意外执行此前停用的第三方代码。
- 已安装外源包和数据保持不变，随后由插件管理页面展示。

## 备选方案

- 继续使用仓库注册表：保留可审查性，但本机状态和 Git 声明容易漂移，且操作步骤过多。
- 直接修改 Profile 文件而不调用官方 CLI：减少子进程，但会复制 DSH 的 Bundle 对账逻辑并耦合私有实现。
- 允许全部 pnpm spec：兼容性更强，但扩大命令输入和供应链攻击面。
- 自动重启 DSH：操作更短，但插件无法可靠、安全地重启承载自己的宿主进程。
- 不执行失败补偿：实现较简单，但 CLI 失败可能留下部分写入。选择尽力补偿并二次核对，同时保留 CLI 紧急恢复，因为进程中断、registry 故障或宿主无法启动时仍不能保证事务完整性。

## 结果

正常插件管理不再要求编辑仓库文件或手工运行同步命令。Profile 是唯一安装事实来源，仓库只维护管理器代码和接入。失败操作会尽力恢复到开始前的精确版本，但这不是跨进程、跨 registry 的强事务保证；若第三方插件导致 DSH 无法启动，用户仍需使用文档中的单条官方 CLI 卸载命令紧急恢复。

本决策取代 ADR-006，并延续 ADR-001 的官方启动命令、ADR-002 的工作区插件接入方式和 ADR-003 的 DSH Home 状态所有权。

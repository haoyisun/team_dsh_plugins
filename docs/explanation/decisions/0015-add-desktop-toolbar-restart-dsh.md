# ADR-015：在 Desktop 工具栏提供重启 DSH

## 状态

Accepted

## 日期

2026-09-09

## 背景

插件 Bundle 与 MCP 变更需要重启 DSH Web 才生效。ADR-010 已在托盘提供“重启 DSH”，
但 ADR-014 证明托盘入口不易发现；版本与“检查更新”因此进入窗口工具栏，重启仍只留
在托盘。

若工具栏按钮只写“重启”，会与退出 App 或重开 Electron 壳混淆。桌面壳也不应重启整
个 Electron：那会重跑单实例、端口预检和版本选择，而插件生效只需要回收当前 DSH 进
程并加载新的 loopback token URL。

## 决策

- 壳工具栏在版本标签右侧增加“重启 DSH”，控件结构、间距和视觉样式与现有“检查
  更新”按钮相同；不引入新的按钮层级，也不把操作推到工具栏右侧。
- 按钮文案固定为“重启 DSH”，不使用单独的“重启”。托盘菜单继续使用同一文案，
  作为窗口不可见时的等价入口。
- 本地工具栏通过 `dsh-desktop://restart` 请求 main process。busy 时两个工具栏按钮
  一并禁用；重启过程显示与“检查更新”相同的旋转加载态，文案为“重启中…”。
- 重启只停止当前 supervisor 管理的 DSH 进程树，等待 `127.0.0.1:3080` 释放，再启动
  已固定的精确版本并加载新的 token URL。不查询 `latest`，不重跑首次版本确认，不弹
  确认框，也不重启 Electron。
- 真正的启停仍复用现有 `runSelectedDsh` / `activateDshRelease` 路径；DSH 页面不能
  获得进程管理 IPC。

本 ADR 补充 ADR-014 的工具栏操作；ADR-010 的进程所有权、Job Object 清理和 token
脱敏，以及 ADR-013 的精确版本固定策略保持不变。

## 备选方案

- 按钮只标“重启”：更短，但无法区分重启 DSH 与重启桌面壳。
- 重启整个 Electron：实现直观，但会丢失窗口并重复预检，超过插件生效所需范围。
- 向 DSH Web 注入重启按钮：可出现在插件“待重启”提示旁，但会破坏壳与 DSH DOM
  的隔离，并把进程管理暴露给远程页面。
- 重启前确认：能避免打断进行中的会话，但壳无法得知 DSH agent 状态，且同版本重启
  是预期的频繁操作；升级确认仍由 ADR-013 覆盖。

## 结果

用户无需打开托盘即可重启当前固定版本的 DSH Web。Electron 冒烟测试覆盖按钮文案、
与“检查更新”的计算样式一致、`dsh-desktop://restart` 动作以及重启加载态。
